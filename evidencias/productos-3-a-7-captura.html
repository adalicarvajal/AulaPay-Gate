Producto 3 - Correccion del codigo vulnerable

Antes: concatenacion vulnerable

const query =
  "SELECT id, student_id, amount, payment_date, receipt_url " +
  "FROM payments WHERE student_id = " + studentId;

RIESGO El identificador se incorporaba directamente a la consulta SQL.

Despues: consulta parametrizada y autorizacion

if (requestedStudentId !== authenticatedStudentId) {
  return res.status(403).json({ error: "Forbidden" });
}

const query =
  "SELECT id, student_id, amount, payment_date, receipt_url " +
  "FROM payments WHERE student_id = $1";
const result = await db.query(query, [requestedStudentId]);

CORREGIDO Se valida el propietario y se usa el parametro $1.

Producto 6 - Condicion de aprobacion del gate

GATE APROBABLE CONDICIONALMENTE El despliegue solo puede avanzar cuando todas las condiciones esten verificadas.
  • La API devuelve 403 Forbidden al solicitar pagos de otro estudiante.
  • La consulta SQL usa parametros y no concatena studentId.
  • La dependencia esta en 2.4.3 o una version corregida.
  • El supuesto secreto esta validado como falso positivo y sustituido por placeholder.
  • Las pruebas automatizadas pasan. Si falla una condicion, el gate permanece bloqueado.
